Что это значит, без приукрашивания:

* **Первая страница не стала быстрее**: при тёплом кэше 0,8–1,0 с против 0,60 с у старой версии.
  Старая версия брала первые 25 найденных и останавливалась; новая обязана построить весь набор,
  чтобы отсортировать его глобально. ~60 % времени — проверка свежести кэша (хеширование каждой
  строки `jobs`), её убирать нельзя: иначе устаревший «барьер» скроет вакансию.
* Стала быстрее и дешевле **вся работа с очередью**: полный проход 34,7 с → 15–17 с при том же кэше,
  SQL-запросов 22 528 → 1 036, живых оценок 1 093 → 0; страница стоит ~0,5–0,6 с независимо от
  глубины (раньше росла до 2,2 с).
* Состав очереди идентичен: 682 вакансии до и после при тёплом кэше (сравнение множеств id).
* На холодном кэше (так будет сразу после деплоя) страница ограничена 60 живыми оценками
  (~2,3–2,6 с), показывает 16 записей, все 8 Junior Python/Backend найдены, и явно сообщает, что
  3 174 вакансии не пересчитаны.
* Сортировка теперь глобальная (раньше — только внутри страницы, «other»-группа не сортировалась
  вообще), пагинация keyset по ключу сортировки: без дублей, устойчива к новым вакансиям.
* Измерения сделаны один раз на одной машине (Windows, SQLite) — это порядок величин, не бенчмарк.

Известный дефект вне объёма #52: правило `classify_work_time` помечает `PART_TIME` вакансии, где
«Teilzeitmöglichkeiten» / «part-time options» — лишь перечисленное преимущество (id 705, 752,
1337). Исправление меняет хеш правил и обнуляет весь кэш, поэтому вынесено в отдельное изменение.
Подробности: `docs/JUNIOR_REVIEW_VACANCIES.md`.

## 6. План релиза

### 6.1 Безопасно до merge (read-only, разрешение не нужно)

1. Дождаться зелёного CI на #52 (в т.ч. job `scheduler-postgres` — локально PostgreSQL недоступен,
   эти тесты выполняются только в GitHub Actions).
2. Проверить, что все PR цепочки содержат одну голову Alembic (`alembic heads`).
3. Прочитать `docs/AUDIT_2026_11_06_DEPLOYMENT_PLAN.md` и `docs/NATIONWIDE_REMOTE_DISCOVERY_ROLLOUT.md`.
4. Посмотреть `/ui/review` и `docs/JUNIOR_REVIEW_VACANCIES.md` на копии БД.

### 6.2 Требуют разрешения оператора

1. **Проверка `.env`** на шаблонные `API_KEY`/`UI_SESSION_SECRET`/`POSTGRES_PASSWORD` (после #37 приложение
   не стартует с шаблоном) — булевой проверкой из `AUDIT_2026_11_06_DEPLOYMENT_PLAN.md` §2, без вывода секрета.
2. **Merge в `main`** по порядку: #47 → (перенацелить #48 на `main`) → #48 → #49 → #50 → #51 → #52. После
   каждого — зелёный CI. Старые PR ветвей аудита (#32–#46) закрыть без слияния.
3. **Резервная копия** рабочей БД: `python scripts/backup_sqlite.py --db runtime/job_triage_runtime.db
   --dest C:\Users\V\JobTriage-Backups --label pre-release` (проверяется SHA-256 и целостность).
4. **Миграция** `alembic upgrade head` на рабочей БД (одна аддитивная колонка).
5. **Перезаполнение кэша**: `scripts/stage21_assess_vacancies.py --database runtime/job_triage_runtime.db
   --apply --snapshot <каталог>` (~2–3 мин для 3 234 вакансий).

### 6.3 Требуют остановки работающей системы

Миграция и перезаполнение кэша пишут в SQLite; `journal_mode=delete`, поэтому один писатель за раз.
Перед шагами 6.2.3–6.2.5 остановить `uvicorn` и `app.scheduler`, убедиться, что процессов нет; запускать
снова только после проверки §6.4. Восстановление из бэкапа (§6.5) тоже только при остановленном приложении.

### 6.4 После деплоя

1. `alembic current` = `a7c3e5f1b9d2`; счётчики: 25 Bewerbungen, 54 события, вакансий ≥ 3 234.
2. `/ui/review`: нет заметки «не пересчитано» (кэш свежий), 8 Junior Python/Backend первыми.
3. Планировщик **не включать** автоматически; `NATIONWIDE_REMOTE_DISCOVERY_ENABLED` оставить `false`,
   пока оператор не решит иначе (`docs/NATIONWIDE_REMOTE_DISCOVERY_ROLLOUT.md`).
4. Проверить, что исходящих писем/сообщений не было (журнал отправок пуст, Gmail drafts без изменений).

### 6.5 Rollback

1. Остановить приложение и планировщик.
2. `python scripts/restore_sqlite.py --backup <pre-release.db> --target runtime/job_triage_runtime.db
   --replace --allow-production` (сверяет цифровой отпечаток sidecar). Откат кода: `git revert` слияний
   в обратном порядке либо деплой предыдущего тега.
3. Миграция обратима и без восстановления: `alembic downgrade -1` удаляет `jobs.full_time_offered`.
4. Кэш `job_fit_assessments` при откате можно оставить: устаревшие строки не используются.
