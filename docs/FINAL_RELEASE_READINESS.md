## 3. Fit-кэш и порядок его обновления

Правила изменились несколько раз по цепочке (в т.ч. в #53 — классификатор рабочего времени входит в
замыкание хеша правил): все 3 234 строки `job_fit_assessments` рабочей БД сейчас STALE и останутся
STALE после merge любого PR цепочки. Последствия: `/ui/review` на холодном кэше показывает не более 60
живых оценок за запрос (Junior Python/Backend первыми), пишет сколько вакансий не пересчитано и, значит,
**неполон**. Безопасный порядок:

1. Остановить приложение и планировщик (§5).
2. Бэкап (§5.1) и `alembic upgrade head`.
3. Перезаполнить кэш явно: `python scripts/stage21_assess_vacancies.py --database <db> --apply
   --snapshot <каталог>` (на копии: 3 234 строки за ~2 мин 15 с, повторный запуск пишет 0 строк).
4. Запустить приложение, проверить `/ui/review` (нет заметки «не пересчитано»).

Кэш никогда не заполняется из HTTP-запроса и автоматически.

1. Остановить приложение и планировщик.

4. Кэш `job_fit_assessments` можно оставить: устаревшие строки не используются.
