## 5. Остающиеся эксплуатационные риски

- **Аутентификация отправителя (TASK 21).** Подтверждение и отправка ответа возможны только при сохранённом выровненном DMARC; сейчас Gmail-сообщений и одобрений в базе нет, поэтому потери нет. Для будущих писем без DMARC — отвечать вручную. DMARC подтверждает домен, не человека; право записи в ящик позволяет подделать доверенный заголовок.
- **Блокировка одного процесса.** При `SHARED_STATE_BACKEND=memory` второй веб-процесс не стартует (проверено). Файл блокировки по умолчанию лежит во временной папке: разные учётные записи/контейнеры его не разделяют. Держите один процесс; для нескольких — отдельное решение (`database`).
- **Telegram.** При обычном запуске с реальным токеном веб-процесс запускает Telegram-бота (как и раньше).
- **Новые операторские ограничения:** `refresh-ba --apply` и `backfill --apply` теперь занимают общий слот коллекторов; во время работы планировщика/запуска они отклоняются.
- **Миграции:** число миграций выросло (замечание Артура о частоте схемных изменений сохраняется).
