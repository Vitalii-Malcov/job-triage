## 2. До слияния SEC-02 (#37): проверка `.env` — РАЗРЕШЕНИЕ

После #37 приложение **не стартует**, если `API_KEY`, `UI_SESSION_SECRET` или `POSTGRES_PASSWORD` равны шаблонному значению из старого `.env.example`. Проверка без вывода секрета (PowerShell, только булево):

```powershell
$v = (Select-String -Path .env -Pattern '^API_KEY=(.*)$').Matches.Groups[1].Value
"API_KEY empty: $([string]::IsNullOrEmpty($v))   template: $($v -match '^replace[-_ ](with|me)')   length>=32: $($v.Length -ge 32)"
```

Если `template: True` — сначала сгенерируйте ключ (`python -c "import secrets; print(secrets.token_urlsafe(32))"`), впишите в `.env`, перезапустите клиентов, и только потом сливайте #37. Ключи короче 32 символов продолжают работать со старым поведением блокировки.

## 7. Известные эффекты деплоя (чтобы не удивиться)

* **#37**: ключ <32 символов — как раньше; ≥32 — верный ключ больше не блокируется чужими неудачными попытками; шаблон в `.env` — отказ старта (п. 2).
* **#38/FLOW-04**: ответы на `noreply@…`/`bounce`/`postmaster` не создаются/не отправляются (раньше уходили в никуда). Если среди одобренных, но не отправленных черновиков есть такой адрес — отправка будет честно отклонена.
* **#38/FLOW-01**: «Новая вакансия» приходит один раз (и ещё раз, когда вакансия впервые становится APPLY ≥ порога); раньше — каждый прогон.
* **#36**: `POST /jobs/score` с названием > 300, описанием > 100 000 символов или > 200 навыков → 422 (раньше принималось без границ); id вне int64 → 422 вместо 500.
* **#41**: 5 групп дублей BA (все `NEW`) в копии прод-БД **не сливаются**; слияние — вручную по `scripts/vacancy_identity_report.py`, затем (по решению) уникальный индекс.
* **#43**: бот при неудачном старте повторяет попытки (5 с → 5 мин) вместо «навсегда выключен»; неверный токен — один раз в журнал и без повторов.
* **#39**: старт планировщика отказывает, если `AUTOMATION_SCHEDULER_ACCOUNT_KEY` ≠ `GMAIL_USERNAME` в нижнем регистре при включённом Gmail-цикле.
