## Вывод анализа

Расхождение оценок **не было регрессией PR #30**. Классификация обоих явлений:
`EXPECTED_POLICY_CHANGE` (проверено независимым ревью Codex).

## 1. 154 вакансии с устаревшим `jobs.score` / `jobs.recommendation`

* Старый код (`78a947b`, до PR #30) и новый (`d0f576e`) давали одинаковые `(score, recommendation)` для
  всех 3 234 вакансий.
* Сохранённое значение и свежий пересчёт различались у 154 вакансий (на выборке из 400 — у 16). У всех 154
  `last_seen_at` раньше 2026-10-27 14:49 — момента профиля кандидата v5 (добавлены навыки Pydantic,
  Django REST Framework, AWS, Terraform, AI/LLM integrations).
* Контрфактическая проверка: без этих пяти навыков все 154 значения воспроизводятся точно; вакансии,
  увиденные после v5, совпадают с текущим профилем; несовпадений без объяснения нет.
* Причина: оценка пересчитывается при повторном сборе вакансии, а не при изменении профиля, поэтому
  нетронутые вакансии хранят оценки «до v5».
* Матрица рекомендаций (сохранённая → свежая): SKIP→SKIP 2 717, MAYBE→MAYBE 225,
  NEEDS_ENRICHMENT→NEEDS_ENRICHMENT 268, APPLY→APPLY 16, SKIP→MAYBE 7, SKIP→APPLY 1. Переходов вниз нет.
  Вакансии, связанные с Bewerbungen (17), не менялись.

## 2. Случай SKIP → APPLY (job 38)

«Data Engineer», обязательные AWS/Python/SQL: было 58 SKIP, при пересчёте 82 APPLY, потому что AWS стал
навыком кандидата. `fit_tier` при этом `NOT_SUITABLE` (требуется опыт 2+ года).

Политика скоринга: у навыков AWS/Terraform/AI-LLM в профиле стоит пометка «learning/project experience
only — not commercial»; скоринг учитывает только имена подтверждённых навыков и пометку игнорирует
(по оценке Codex — политика проекта, не дефект). Из 17 вакансий с APPLY по баллам 4 опирались на AWS
(3 из них `NOT_SUITABLE`, 1 `STRETCH`). Вопрос политики «learning only» остаётся решением оператора.

## 3. Почему все записи `job_fit_assessments` были устаревшими

Ключ кэша включает хеш исходников модулей правил (`fit_cache.compute_rules_hash`): любая правка этих
модулей (даже комментарий) инвалидирует весь кэш. Кэш был устаревшим и до PR #30. Пересчёт на копии:
169 изменений уровня, все в сторону `NOT_SUITABLE` — 168 из-за правила роли «IT-поддержка/администрирование
— не целевая роль» (добавлено 2026-11-01 21:35, после заполнения кэша в 16:22), 1 — вакансия 2892 стала
`ALREADY_APPLIED` (заявка №24, REJECTED 04.11). Распределение после пересчёта на тот момент:
NOT_SUITABLE 2 148, NEEDS_OPERATOR 935, STRETCH 140, PARTIAL_MATCH 11, GOOD_MATCH 0.

## 4. Найденные тогда дефекты и наблюдения

* **D1** — заголовки вроде «IT-Administratoren», «Systemadmin Linux», «Anwendungssupporter IT» (мн. число,
  сокращения, составные слова) не попадали в семейство «поддержка/администрирование». Исправлено в PR #32
  (`app/agents/target_role.py`, регулярные выражения), влит.
* **D2** — `app/services/shortlist_gate.py` (читает fit-tier) тогда вызывался только из тестов; авто-шорт-лист
  выбирал по `jobs.recommendation` и баллу без `fit_tier`. Отправки нет в любом случае, нужно одобрение
  человека. Статус после Stage 62 смотрите в `docs/STAGE62_FINAL_STABILIZATION_REPORT.md`.
* **D3** — поле `decision` (`BLOCKED/NEEDS_VERIFICATION/CANDIDATE`) не согласовано с `fit_tier`: тогда у
  36 вакансий `decision=CANDIDATE` при `NOT_SUITABLE`. Для фильтрации опирайтесь на `fit_tier`.
  (Подтверждено снова 2026-11-12: после пересчёта навыков job 1528 получил `CANDIDATE` при `NOT_SUITABLE`.)
