## 6. Оставшиеся ограничения и риски

1. Реальные письма не отправлялись; поведение с настоящим Gmail (заголовок `Authentication-Results`) проверено на двух реальных рассылках и тестами, но валидация на отдельном нерабочем ящике остаётся шагом перед включением отправки (CLAUDE.md, Stage 9D).
2. После обновления ответы на **старые** письма из системы невозможны (нет сохранённого DMARC) — отвечать вручную. Ответы на письма от доменов без выровненного DMARC тоже.
3. XING: идентичные объявления в разных письмах не различаются; возможен один «двойник» при смене зарплаты.
4. Включение `SHARED_STATE_BACKEND=database` — отдельное решение; каждый воркер всё равно запускает свой Telegram-поллер (нужен пустой токен у воркеров).
5. Блокировка единственного процесса работает на уровне общей папки (по умолчанию temp): контейнеры с раздельными ФС ею не связаны.
6. Кэш оценок вакансий (`job_fit_assessments`) после обновления может стать `stale` — нужен одобренный refill (раздел 6b плана).
7. CI: предупреждения Node 20 / `ubuntu-latest` — не блокируют.
8. Число миграций растёт (замечание Артура о churn остаётся в силе).
